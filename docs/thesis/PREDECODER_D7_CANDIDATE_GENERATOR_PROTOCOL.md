# d7 후보 생성기 대조 실험 규약

2026-11-17 · 개발 맵에서 국소 규칙의 반경을 선택하고, 새 평가 맵을 생성하기 전에 규칙과 평가 설정을 고정한다.

## 비교 조건

기존 최종 평가의 강한 ZZ 조건 G₁(`zz_factor=0.25`)을 사용한다. d7, 7라운드, Bell-pair Z readout, `p=0.0015`에서 맵마다 G₀(`zz_factor=0.05`) 회로의 DEM D₀과 일반 PyMatching을 사용한다. 같은 맵의 두 강도는 이상 회로를 공유한다. 각 방법은 같은 G₁ shot, 원본 예측, 후단 디코더를 사용한다.

- **학습 후보.** 재학습 checkpoint 0–7의 학습된 1·2비트 motif와 detector별 CNN 확률로 정렬한 기존 후보 순서를 사용한다. 배치 후보 생성 경로를 별도로 실행하고, 개발 맵 4개에서 후보 mask, 후보 순서, 논리 예측을 기존 저장 배열과 전수 대조한다. detector-event fraction context는 기존 고정값을 사용하고 정답 집계 채널은 0으로 둔다.
- **국소 열거.** 활성 detector 하나를 뒤집거나, 활성 detector를 하나 이상 포함하고 시간·행·열 인덱스의 맨해튼 거리가 반경 이내인 detector 쌍을 뒤집는다. 양쪽 활성인 쌍, 활성 단일 비트, 한쪽 활성인 쌍 순으로 배열한다. 같은 유형은 거리, detector 인덱스 순으로 정렬한다. 반경 2와 4 중 기존 개발 맵 787000–787003에서 후보 32개의 평균 오답 회복률이 높은 값을 고른다. 동률이면 2를 사용한다. 후보 생성에 정답, 학습 motif, CNN, 후단 논리 클래스 조회를 사용하지 않는다.

두 방식 모두 원본 유지 1개와 고유 비영 후보 최대 32개를 허용한다. 비영 후보 수가 부족하면 가능한 후보만 사용한다. 편집된 syndrome에 perfect matching이 없으면 해당 후보는 회복률과 클래스 수에 기여하지 않으며 실패 건수에 기록한다. 그 외 디코딩 오류는 중단한다. 비교는 두 후보 생성 방식 전체에 대한 것이다. 학습 motif의 범위와 CNN 순위 효과가 함께 달라진다.

## 새 맵과 분석

맵은 788200–788223의 24개를 사용한다. sampler seed는 1794200–1794247이고 맵마다 G₀ 다음 G₁ 순이다. G₀ 32 shot은 맵별 D₀ 생성에 사용한다. G₁은 맵당 512 shot, 합계 12,288 shot이다. 기존 평가 case와 학습 기록을 대조해 맵 및 sampler seed 중복 여부를 확인한다. 규칙 선택 결과, seed, checkpoint, 실행 코드 해시와 패키지 버전을 동결 파일에 남긴다.

주 지표는 32개 예산에서 원본 오답 중 정답 논리 클래스를 내는 후보가 하나 이상 있는 비율이다. 맵마다 학습 방식은 8개 checkpoint의 비율을 동일 가중 평균한다. 규칙 방식은 같은 shot에서 한 번 평가한다. 맵별 두 비율 차이(학습 − 규칙)의 평균과 양측 95% Student t 구간을 보고한다. 간격은 고정한 8개 checkpoint에 조건부다. 구간 하한이 0을 넘으면 이 조건에서 학습 방식의 회복률 우위를 확인한다.

예산 4·8·16의 결과는 기술 통계다. 예산별 oracle 정확도, 서로 다른 논리 클래스 수, 실제 후보 수와 전체 예산에서의 편집 weight 분포를 함께 기록한다. 생성 시간은 같은 CPU와 두 PyTorch 스레드에서 batch별 mask 준비 시간으로 측정한다. 후보 템플릿 준비와 후보의 후단 디코딩 시간은 별도로 집계하고 checkpoint 로딩과 데이터 I/O는 제외한다. Oracle은 정답을 사용해 계산한 후보 집합의 상한이다. 실제 채택 정책의 순이득은 이번 실험 범위 밖이다.
