# d7 후보 생성 전 게이트 평가 규약

2026-11-17 · 개발 맵에서 게이트를 선택하고, 새 잡음 맵을 생성하기 전에 계수와 기준값을 동결한다.

## 게이트 개발

후단은 기존 d7 checkpoint 0–7의 학습 후보와 동결된 논리 클래스별 채택 모델이다. 후단 채택 기준값은 0.025다. 게이트 입력은 같은 shot의 첫 일반 MWPM에서 반환한 원본 비용과 라운드별 detector event 수다. 게이트는 표준화한 입력과 절편을 사용하는 선형 ridge 회귀다. L2 계수는 0.10이다.

개발 맵 788200–788223에서 복구는 기존 후단이 원본 오답을 맞힌 경우, 악화는 기존 후단이 원본 정답을 틀리게 바꾼 경우다. 두 경우를 각각 +1과 −1, 나머지를 0으로 두고 checkpoint 8개에서 평균해 shot별 학습 목표를 만든다. 목표는 기존 후단의 저장 교차검증 예측으로 계산한다. 게이트 적합은 개발 맵 하나씩 제외하는 방식으로 수행한다. 두 단계의 개발 교차검증은 중첩 실행하지 않으며 새 맵을 최종 평가에 사용한다.

통과 목표 비율은 5·10·20·40·60·80·90%다. 각 fold에서 학습 점수의 분위를 기준값으로 정하고 기준을 엄격히 넘은 shot에서 후단을 실행한다. 제외한 맵에서 **막은 악화 − 놓친 복구**를 합산해 가장 높은 비율을 선택하고, 동률이면 더 낮은 통과 비율을 고른다. 항상 실행과 항상 원본 유지는 진단의 기준점이다. 선택한 비율의 절대 기준값과 회귀 계수는 개발 맵 전체로 다시 적합해 동결한다.

## 새 맵과 비교

평가는 d7, 7라운드, Bell-pair Z readout, `p=0.0015`의 강한 ZZ G₁(`zz_factor=0.25`)에서 같은 맵의 G₀(`zz_factor=0.05`) DEM D₀를 사용하는 일반 PyMatching을 기준으로 한다. 맵 seed는 788400–788423, 샘플 seed는 1794400–1794447로 맵마다 G₀ 다음 G₁ 순이다. G₁은 맵당 512 shot으로 12,288개이며 G₀ 32 shot의 회로에서 D₀를 얻는다. 기존 평가와 학습 기록에서 seed가 겹치는지 검사한다.

같은 batch에서 PyMatching 단독, 기존 후단 정책, 같은 후단에 게이트를 추가한 정책을 비교한다. 게이트가 차단한 shot의 최종 예측은 원본 MWPM이다. 통과한 shot만 클래스별 제약 matching 비용 계산과 후보 생성 및 채택을 수행한다. 분리 배치 실행 결과가 통과 shot에서 기존 후단과 일치하는지 모든 모델에서 확인한다. 두 observable을 모두 맞힌 경우만 정답이다.

정확도는 각 맵에서 고정 checkpoint 8개의 결과를 동일 가중한다. 맵별 짝차이 24개의 평균과 양측 95% Student t 구간을 보고한다. 주 비교는 게이트 경로 대 PyMatching 단독이다. 기존 후단 대비 효과는 차단한 악화 수와 놓친 복구 수의 차이로 교차 확인한다. 게이트 실행률은 물리 shot을 분모로 보고한다.

## 시간 측정과 채택 기준

각 맵에서 정확도 평가 batch 전체 512개를 사용한다. 시간 측정의 checkpoint는 맵 순서에 따라 0–7을 순환해 각 checkpoint가 3개 맵에 배정된다. 세 경로를 같은 CPU 프로세스에서 각각 1회 예열하고 3회 측정한다. 맵과 반복 순번으로 경로의 실행 순서를 순환한다. 첫 MWPM, 실행한 특징 계산과 게이트, 클래스별 비용, 후보 생성, 후보 후단 디코딩, 채택을 측정에 포함한다. 파일·checkpoint 로딩과 정적 맵 구조 준비는 제외한다. 측정된 예측을 정확도 평가의 동일 맵·checkpoint와 대조한다.

맵마다 경로별 반복 중앙값을 구하고 경로별 맵 중앙값을 보고한다. 시간 기준은 맵별 기존 후단과 게이트의 반복 중앙값 차이(기존 − 게이트)의 평균이 양수인 경우다. **시간 기준을 충족하고 PyMatching 단독 대비 정확도 차이의 95% 구간 하한이 0보다 클 때** 게이트를 채택한다. 시간은 줄었으며 정확도 구간에 0이 포함되면 실행 시간 감소와 정확도 불확실성을 함께 보고한다.
