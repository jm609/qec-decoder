# d7 matching 비용 기반 후보 재순위 평가

2026-11-16 · Anaconda `fp` 활성화 상태에서 실행

**matching 비용 항은 수정 후보를 바꿨으나, 수정할 shot을 고정하면 논리 예측은 한 건도
바뀌지 않았다.** 원본 유지도 허용하면 강한 ZZ 조건에서 기존 1위 적용보다 정확도가
0.275 pp 올랐다. 이득은 수정 취소에서 나왔고, 원본 PyMatching 대비 순이득은
−7.126 pp였다. [집계 JSON](../../../artifacts/eval/d7_matching_rerank/20261116/summary.json)

## 실험 조건

잡음 변화 평가에서 사용한 d7 checkpoint 2, 11, 54, 57과 동일한 후보 생성·입력 context를
유지했다. `zz_factor=0.05`(G₀)와 `0.25`(G₁) 모두 D₀ 일반 MWPM을 사용했다. 신경망의
기존 후보 점수에 다음 항을 더했다.

```text
보정 점수 = 기존 점수 + λ × clip((원본 matching 비용 − 수정 후 비용) / max(|원본 비용|, 1), −1, 1)
```

비용은 PyMatching이 반환한 최적 matching의 가중치 합이다. 서로 다른 syndrome에서 얻은
비용 차이를 논리 정답 확률로 해석할 근거는 없다. 이 실험에서는 후보 순위를 바꾸는
특징으로 사용했다.

주 비교는 G₁에서 기존 1위가 수정한 shot을 그대로 유지하고, 각 shot에서 비영 수정
후보의 순위만 바꾼 결과이다. 원본 유지까지 다시 고르는 경로는 보조 비교로 계산했다.
개발 G₁ 맵 2개에서 λ ∈ {0.25, 0.5, 1, 2, 4}를 비교했다. 다섯 설정이 모두 순이득
0이어서 사전 동률 규칙에 따라 가장 작은 0.25를 고정했다. 개발 데이터에서 바뀐 비영
수정은 계수에 따라 11–139건이었고, 해당 논리 예측은 동일했다. 개발 과정에서 기존에
저장한 D₀ 원본·후보 예측을 matching 비용을 함께 반환하는 경로에서 그대로 재현했다.
[개발 민감도](../../../artifacts/eval/d7_matching_rerank/20261116/development_action_sensitivity.json)

이후 이전 잡음 변화 평가와 겹치지 않는 맵 8개(784100–784107), 맵·강도당 1,024 shot을
평가했다. 두 강도 합계는 16,384 shot이다. 네 모델이 같은 shot을 공유하며 모델과 맵을
동일 가중했다. 주 비교 구간은 맵 단위 paired bootstrap 20,000회로 계산했다.
[고정 규약](../../../artifacts/eval/d7_matching_rerank/20261116/protocol.json)

## 결과

| ZZ 강도 | 기존 1위 | 수정 shot 고정 재순위 | 원본 유지 허용 재순위 | 후보 oracle |
| --- | ---: | ---: | ---: | ---: |
| G₀ | −8.151 pp | −8.151 pp | −7.913 pp | +10.602 pp |
| G₁ | −7.401 pp | −7.401 pp | −7.126 pp | +12.479 pp |

표의 순이득은 모두 같은 shot의 원본 PyMatching 대비이다. 수정 shot을 고정하면
G₀에서 33건, G₁에서 25건의 mask가 바뀌었지만, 두 observable 예측은 모든 shot에서
기존 1위와 일치했다. 따라서 주 비교는 0.000 pp이고 95% 구간은 [0.000, 0.000] pp이다.
이 구간은 관측한 맵의 차이가 모두 0이라는 뜻이다. 다른 matching 특징이나 계수까지
효과가 없다고 일반화할 수 없다.

G₁의 보조 경로에서는 기존 수정 131건이 원본 유지로 바뀌어 111건을 고치고 20건을 새로
틀렸다. 원본 유지에서 새 수정으로 바뀐 1건도 오답이 됐다. 양쪽에서 수정한 shot은 논리
예측이 그대로였다. 기존 1위 대비 순증 90건, +0.275 pp는 이 채택 변화에서 나왔다.
이 비교에서는 기존 family gate의 도입 성능을 평가하지 않았다.
